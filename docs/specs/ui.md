# Spec: Screen layout and styling

Covers FR-BLK display, FR-TAG display, FR-FMT-01, FR-KEY-04–06, FR-UI-05–11, FR-SET-02–03, N-PORT-02 and N-PORT-04.

- **Sidebar** (FR-UI-01) on the left, 24–32 columns: the Today entry, then a blank line and the bookmarks, each its text alone, under a Bookmarks heading, then a blank line and the project tree under a Projects heading; a section without entries has no heading. The headings, bookmarks and top-level projects start in the same column, projects 2 columns more per level, each right behind its fold marker, which for a top-level entry stands in the gutter (D-60, D-61, D-68). A project with open tasks shows their count, as a collapsed block counts them (§2, D-67), sub-projects included, dimmed and right-aligned against the sidebar's rule, its text cut off one space before the count; a project with none, bookmarks and Today show no number (D-73). While the sidebar has the keys, its focused entry is marked like the outline's focused block (§2); while the pane has them, the entry of where the focused pane is gets a selected block's dimmed marker instead and is scrolled into view (D-68).
- **Panes** (FR-UI-02) to its right as columns, each with a breadcrumb header (its first row, a house icon `⌂` for the document root followed by the path to the zoom block, D-32, starting after the focus gutter of §2 so the root crumb lines up with top-level blocks, D-35) or, in the Today view, the Today icon and the name `Today` in its place ([navigation.md §7](navigation.md#7-today-view-fr-tag-04-d-7)) separated from the outline by a dim horizontal rule, like Workflowy (D-29), and, when zoomed, a title row showing the zoom block styled as in §2 for its type (marker, color, dimming, a project's `:`), in bold and without indent, so its type is clear (D-34). Panes are separated by a dim vertical rule; only the focused pane shows its focus marker (§2), and the other panes' breadcrumbs are dimmed, so the focused pane's header stands out.
- **Status line** at the bottom: mode, file path (marked when it is a `/tmp` file not yet saved elsewhere), save state or error, pending key prefix, transient messages.
- **Secondary sidebar** on the right, 32–40 columns, shown only while it holds the `?` shortcuts panel (§4) (D-28, D-66). It takes its width from the panes, which keep their minimum and scroll horizontally as in [navigation.md §5](navigation.md#5-panes-fr-ui-02--fr-ui-04-d-13). Below 80 columns it is drawn over the right part of the focused pane.
- **Pickers and prompts** (Go to Symbol, Go to Project, Go to Command, Move to, type, color, Save As) are centered overlays at most 80×20; the finders (Go to Symbol, Go to Project, Go to Command, Move to) have their border and title in the accent color, like the command menu.
- **Date prompt** (`ms`/`md`, D-54): a panel across the full width just above the status line, a bordered box titled with the date it sets, its border and title in the accent color, holding the typed text and the preview below it. While it is open the outline gives up its rows, scrolling only if the focused block would otherwise be under the panel, and everything else on screen (breadcrumbs, outline, status line) is dimmed with the terminal's dim attribute.
- **Dialogs dim the screen behind them** (D-69): while a dialog that takes the keys is open (the finders, the theme chooser, the type and color pickers, the details popup, the context menu, Save As, the settings window and its value picker, the date prompt and the conflict prompt), everything drawn behind it, the sidebar, panes, shortcuts panel and status line included, takes the terminal's dim attribute, as for the date prompt; the dialog itself does not. The attribute keeps every color, so it reads the same in every theme and color depth. The edit-mode command menu and the shortcuts panel are not dialogs: the text being typed and the outline stay as they are.
- Below 80 columns the navigation sidebar hides; below 40×10 only the focused pane and the status line are drawn.
- A wide character (CJK, emoji) that a popup, a panel or the screen's edge covers in part is hidden whole, so no grapheme is split and the popup's edge shows (N-PORT-04).

## 2. Blocks

Each row: indent, then the marker (if the type has one) and a space, then text, the `@today` and bookmark icons, and right-aligned chips. The indent is exactly the block's depth in the hierarchy, 2 columns per level, whatever its type; markers and icons come after it and never change it. Only tasks have markers; every other block starts with its text. So a task's text node, being its child, sits one level in and lines up with the task's text, as in TaskPaper (D-31).

An entry of the Today view has no indent and shows its breadcrumb path dimmed after its icons, two spaces after them, the crumbs joined by ` › ` ([navigation.md §7](navigation.md#7-today-view-fr-tag-04-d-7)).

| Block (FR-BLK) | Marker | Text |
|---|---|---|
| Project | none | bold heading in the primary color (Textual's `$primary`), ending in `:` as in the file |
| Task | `-`, done `✔` | normal; done tasks dimmed and struck through (falls back to dim), their `✔` dimmed too (D-36) |
| Text | none | slightly dimmed; less dim than done tasks and the other dimmed blocks (D-37). It is the theme's dim-text color (§3). A line carrying `@code` is text like any other (D-43) |
| Section (a text block with `@section`, D-52) | none | bold italic label in the headers color (Textual's `$secondary`, D-49), no rule; children indented below |
| Divider (a text block reading `---`, D-52) | none | in navigate mode a horizontal rule across the pane in the rule-lines color, dimmed further so it is fainter than the header rule (D-33); while edited, its raw `---` in the text style |

- Tasks (normal text), projects and sections (their own colors) stand out; every other block type is dimmed (D-29).
- **Completed blocks** (FR-DONE-01, D-40): any block can be done. A done block keeps its type's marker and color and is dimmed and struck through (falls back to dim), its marker dimmed with it; a done task's marker is `✔` (D-36). Every block inside a done block, at any depth, is dimmed, marker included, but not struck through, since only the done block carries `@done`. The same holds when zoomed: the title row and the rows below it are dimmed when the zoom block or a block above it is done. A divider is already very dim and looks the same when done. The breadcrumb header keeps its style; the title row shows the zoom block's state.
- No fold marker is shown on expanded blocks, since any block can be folded. A block that has children and is collapsed shows `▸ n` after its text and icons, projects included (D-29), where `n` counts the open tasks it hides: every task at any depth below it that is neither done nor inside a done block, so projects, notes, sections and dividers never count, and a collapsed block that is done or inside a done block hides none. With no open tasks hidden it shows `▸` alone (D-67).
- **Tags are never shown** (FR-TAG-01). Their effects are: dates as compact chips (`󱙬 tomorrow`, FR-TAG-03, D-46), `@today` as a star and `@bookmark` as a bookmark icon right after the text, a space before each, the star first, both dimmed with a done block like the date chips and not shown on the block being edited (FR-TAG-04, D-47), a color tag tints the row's background with a very dim shade of its color, from the block's marker to the pane's right edge, leaving the indentation and every text color and style as they are (FR-TAG-05, D-48). Bookmarks are also listed in the sidebar.
- **Date chips** (FR-TAG-03, D-46): right-aligned at the end of the row, the start date before the due date, each a calendar icon (§7) and the date named relative to today's local date: `today`, `tomorrow`, `yesterday`; the weekday (`Tue`) 2 to 6 days ahead; `next Tue` 7 to 13 days ahead; `in 15 days` further ahead; `3 days ago` further back. Start chips are green and due chips red. A due date before today's local date is overdue, unless the block is done or inside a done block, whose chips are dimmed with it; an overdue chip has its own icon and is bold and reversed. A tag whose value is not a date shows no chip. The block being edited shows none. Chips sit on a block's first line, and its text stops before them: it wraps, or with wrap off ends in `…` (FR-UI-05). Chips follow the local date: the screen is redrawn at local midnight while a date chip is shown.
- **Inline formatting** (FR-FMT-01): `**bold**` renders bold and `` `code` `` dimmed, both in the block's own color (D-49), with the markers hidden in navigate mode; edit mode shows the markers.
- **Links** (FR-BLK-06, FR-FMT-03, D-45), in every block and in navigate mode only; edit mode shows the raw text: bare `http(s)://` URLs, `<url>` and `[title](url)` show their title (or URL) in the link style, underlined in the links color over the block's own style, and hide `[`, `](url)`, `<` and `>`. A line carrying `@url(…)` draws its whole title in the link style, its tag hidden like any other.
- **Markdown headings in text blocks**, sections included (FR-FMT-03, D-52, [editing.md §2.2](editing.md#22-markdown-in-text)), navigate mode only; edit mode shows the raw text: headings hide their `#` markers. Level 1 is bold and underlined, levels 2 to 6 bold, all in the text block's own color (D-49). Heading rows keep the block's indentation and get no rule, so they never look like a section.
- **Focus and selection**: the focused block is marked by a `▌` (a half block) in a 2-column gutter left of the outline, on its line (D-30): in the primary color (Textual's `$primary`) in navigate mode and in the accent color (Textual's `$accent`) while editing, so the marker shows the mode (D-51). That line, gutter included and across the pane's full width, also gets the current-line background, a step brighter than the normal one, in navigate and edit mode alike; it changes no text color or style, so dimmed, done and colored blocks look the same as unfocused (D-39). On a block with a color tag, a step brighter shade of its tint takes the band's place from the marker to the right edge; the gutter and indentation keep the band (D-48). The colors are the theme's (§3). Selected blocks get the same `▌`, in the primary color dimmed, so focus and selection line up as one bar (D-51).
- **Edit mode**: the focused block's text becomes a one-line inline editor at the same position, with a visible caret and the markers shown (FR-MODE-02). Text wider than the pane scrolls to keep the caret in view.
- **Wrap** (FR-UI-05): on, long text wraps under its start column; off, every block takes one row and overflowing text ends in `…`. On by default; `word_wrap = false` in `config.toml` turns it off, and the settings window (§8) changes and keeps it; `Alt+z`/`gw` toggles it for the session. Lines break between words, inside a word only when it is wider than a line, and never at the spaces they break at. Every line of a wrapped block gets its focus marker, band and tint, and scrolling keeps all of the focused block's lines in view, or its first lines when it is taller than the pane. When lines reflow (toggling wrap, resizing, narrowing or widening a pane, the `?` panel opening), each pane keeps the same top row (owner, 2026-10-06). The block being edited takes one line (edit mode above). Widths use `unicode-width`; graphemes are never split.

## 3. Themes (FR-UI-06–08)

- Built-in themes: **Terminal Dark**, which uses the terminal's 16 ANSI colors (so it follows the user's palette) and the 256-color grey 248 for notes, plus the twelve truecolor themes of FR-UI-08 ([palettes](../reference/themes.md)), used only when `COLORTERM` indicates support (`truecolor` or `24bit`). There is no light 16-color theme (D-63).
- A theme defines colors for: text, dim text, primary, accent (the focus marker while editing, D-51), selection, focus, current line (the background of the focused block's lines, D-39), headers, rule lines, links, each of the six tag colors and its row tints, plain and focused (D-48), start and due chips, overdue, errors. A truecolor theme also gives the screen its text color and background; Terminal Dark keeps the terminal's. Every theme's dim text differs from its text color and is never a color terminals draw as their default foreground, so notes are dimmed everywhere (D-37, D-63).
- `theme = "<name>"` in `config.toml` chooses the theme, by the name [reference/themes.md](../reference/themes.md#names-and-roles) gives it, such as `nord`; anything else is reported once (FR-SET-04). Default: Terminal Dark (D-63).
- A truecolor theme in a terminal without truecolor, light or dark, is drawn as Terminal Dark, so every theme is usable in 16 colors (N-UX-03, D-63); the choice is kept, and shows in full once the terminal has truecolor.
- **Choose Theme** in Go to Command opens the theme picker: a finder like Go to Command, titled "Theme", listing the built-in themes with the one in use highlighted. It previews each theme live as it is highlighted, by typing or arrows; `Enter` keeps it and saves it to the config (OQ-18, FR-SET-04), `Esc` restores the previous one. A save that fails is reported in the status line, and the theme is kept for the session.
- `NO_COLOR` set (and not empty): no colors, only bold, dim, italic, underline, strikethrough and reverse.
- Unicode markers have ASCII fallbacks (`v`, `>`, `[x]`, `-`, `~` for `⌂`) when the locale is not UTF-8.
- The settings window (§8) previews themes live in the same way.

## 4. Shortcuts panel (FR-KEY-04)

`?` toggles a panel in the secondary sidebar on the right (§1, D-28), listing the most useful bindings for the current mode and context (navigate, edit, sidebar, picker), grouped as in [keybindings.md](keybindings.md) and showing user overrides. A list taller than the panel scrolls (D-55): `)` and `(` scroll it down and up a page in navigate mode, while the panel stays open and every other key keeps its binding; a dim `↑ more` line first and `↓ more` line last show that lines are hidden above or below, each with the key that scrolls that way when that key would scroll, so not while editing, in the sidebar or in a popup. The panel opens at the top. It notes when `Alt` keys have never been received (macOS Option setting) and whether the kitty keyboard protocol is active.

## 5. Context menu (FR-KEY-06)

A popup anchored at the focused element (or at the pointer for right-click) listing every command available for that element, grouped (Edit, Structure, Metadata, View, Panes), each with its key binding right-aligned. Commands that do not apply (for example Open URL on a block without one) are omitted. Entries come from the core's command list for that context, so the menu, the command palette and the `?` panel always agree.

- **Look:** the command menu's box below (title "Commands:", icons, a dim line between groups), placed like it below the focused row from the start of its text, or below the focused sidebar entry, with each command's keys in the primary color at the right and the filter, as typed, in the bottom border.
- **On a block:** Edit, the new-block commands, the clipboard, Duplicate and Delete; the structural commands; status (Complete or Uncomplete, Today, Bookmark or Remove Bookmark); dates; colors; Convert Type with Make or Remove Section; then Zoom In, Toggle Fold for a block with children, Count, Show Details and Open Link for a block with a link; then the Panes group: Open in New Pane, Open Location in New Pane and, while there are other panes, Close Pane. Labels and omissions follow the block's state as in the command menu.
- **On the selection:** the same groups without the commands of one block (editing it, adding blocks, the type picker and the view group), labelled for every selected block: Uncomplete only when all are done, Clear Due Date when any has a due date.
- **In the Today view:** what the view does not take (adding, pasting, indenting, moving, folding) is left out (navigation.md §7).
- **On a sidebar entry** (while the sidebar has the keys): Go to Entry, Open in New Pane, Collapse or Expand Entry for a project entry with child projects, then Return to Outline and Hide Sidebar.
- **On a crumb** (right-click only, since crumbs take no keyboard focus): Zoom Here, or Go Home on `⌂`, unless the pane is there, and Open in New Pane; then Open Location in New Pane and, while there are other panes, Close Pane.
- **On a pane header** (right-click only, outside the crumbs or in the Today view): Zoom Out while zoomed and Go Home away from home; then the Panes group as on a crumb.
- Typing a character that would match nothing is not added to the filter; `Backspace` on an empty filter does nothing.

The command menu of edit mode ([editing.md §2.3](editing.md#23-command-menu), D-50) is a smaller popup of the same kind: a bordered box titled "Commands:", its border and title in the accent color (D-54), on the line below the caret, starting at the caret's column, or above the caret's line when there is no room below, moved left to stay on screen. It is as tall as its entries but no taller than the larger room below or above the caret's line, and scrolls to keep the highlighted entry in view. It lists the matching labels one per line, each after its icon (§7) and padded by 2 columns on each side, the highlighted one reversed, with a dim line across the box between groups, and shows `/` and the filter in its bottom border once one is typed.

## 6. Mouse (FR-KEY-05, D-16)

- Click a block: focus it (navigate mode); click inside the text of the block in edit mode: place the caret.
- Click a fold marker: toggle fold. Click a crumb: zoom the pane there. Click a sidebar entry: go there. Click a pane header: focus that pane.
- Alt+click a block, an internal link (once links exist, FR-OPS-10) or a crumb: open it in a new pane.
- Right-click a block, the selection, a sidebar entry, a crumb or a pane header: open its context menu (FR-KEY-06).
- Wheel: scroll the pane under the pointer without moving focus, 3 lines a step, no further than the first and last lines; the pane stays where the wheel left it until the next key or click, which bring the focus back into view as any motion does. Over the `?` panel the wheel scrolls the panel (D-55).
- A block's row counts from the gutter to the right edge. A click on a block of another pane, a crumb or a pane header gives that pane the keys first, and any click on a pane takes them from the sidebar. A right-click on a block that is not selected clears the selection and focuses the block, so the menu is the block's; on a selected block it opens the selection's menu. A click on the `▸`/`▾` of a sidebar project entry folds or unfolds it, giving the sidebar the keys on that entry.
- While a popup, picker, prompt or the conflict prompt is open, the mouse does nothing.
- Moving the pointer, dragging, releasing a button, the middle button and the sideways wheel do nothing, and the event loop drops them so they draw no frame.
- No feature depends on the mouse; every action above has a key.

## 7. Icons (FR-UI-09, FR-UI-10)

- `icons = "nerd"` (default) draws Nerd Font glyphs; `icons = "none"` draws the Unicode markers of §2. When the locale is not UTF-8, both settings draw the ASCII fallbacks of §3.
- Every icon has exactly one fallback, defined next to it in one table in `ui::theme`, with its ASCII form, so the sets cannot drift. Icons are drawn only by the UI; the core reports types and states, never glyphs. The locale is UTF-8 when the first of `LC_ALL`, `LC_CTYPE` and `LANG` that is set says so; with none set it is not. The table holds: the breadcrumb root `󰋜` (`⌂`, ASCII `~`), a sidebar project's fold `▾` (ASCII `v`) and `▸` (`>`), which also marks a collapsed block's count, and the task markers `-` and `✔` (ASCII `[x]`), these four the same with Nerd Font icons as without (D-59, D-60), the status line's navigate `󰆿` (`↕`) and edit `󰏫` (`✎`) modes and unsaved mark `󰧞` (`●`); the date chips' start `󱙭` (fallback `↦`), due `󱙬` (`⇥`) and overdue `󰨱` (`!`) (D-46), and the `@today` star `󰓎` (`★`) and the bookmark `󰃀` (`⚑`) after a block's text (D-47), which also mark the command menu's date, Toggle Today and bookmark entries and the sidebar's Today entry (D-68), a date entry's icon green or red like its chip. The command menu's other entries (D-54) are project `󰉖` (`▸`), task `󰄱` (`☐`), note, for Note and Remove Section, `󰦨` (`¶`), Make Section `󰚟` (`§`), Complete and Uncomplete `󰗡` (`✓`), the color entries `󰏘` (`●`), each in its color, Show Details `󰋽` (`i`), Open Link `󰌷` (`↗`), Duplicate `󰆏` (`⧉`), Delete `󰧧` (`✕`), and `󰅂` (`›`) for any command without an icon of its own. The finders show each block's type icon (project, note, section), a task's marker, `-` or `✔`, as the outline draws it (D-70), and Move to's Home the root's; Go to Command shows the command menu's icons, Go to Today the `@today` star, Go to Project the project icon, Open Settings a cog `󰢻` (`⚙`), the type picker its types' and the color picker the color icon in each color. The settings window marks its settings: the theme with the color icon, icons `󰠲` (`◇`), word wrap `󰖶` (`↩`), the autosave delay `󰔛` (`◷`), backups and backups kept `󰁯` (`↺`) and the backup folder `󱂀` (`▭`).
- Icons cover: the breadcrumb root (`⌂`), project fold state, a collapsed block's fold marker and open-task count, date chips (start, due, overdue), `@today`, bookmarks, the Today view in the sidebar, the status line's mode and save state, and the entries of pickers, the context menu and the settings window.
- Nerd Font glyphs are taken from the Nerd Fonts v3 code points (not the retired v2 Material Design range) and must be one cell wide in the terminals of N-PORT-01, so layout and alignment are identical with icons on and off; widths come from the same `unicode-width` measurement as text, and a glyph that measures two cells is not used.
- The app cannot detect whether the terminal font has the glyphs. The `?` panel and the settings window's icon entry say how to turn icons off, and the settings window's own labels are plain text, so it stays usable when glyphs render as boxes.

## 8. Settings window (FR-SET-02, FR-SET-03)

- Opened with `g,` in navigate mode or **Open Settings** in Go to Command; a centered overlay like the pickers, but up to 100×30, its border and title in the accent color like the finders.
- Left column: groups (Appearance, Editing, Files); a group shows once it has a setting, so Editing is left out until one exists. Right: that group's settings, two lines each: a `*` when the value differs from the default (the value is then bold too), the setting's icon (§7), its name and, at the right, its current value; below, a one-line description, dimmed. The highlighted group or setting is reversed in the column that has the keys; the highlighted group is bold in the primary color while the settings have them.
- Settings in v1: Appearance — theme (FR-UI-06), icons (§7), word wrap (FR-UI-05), animations (§9); Files — autosave delay and backups: on/off, folder, number kept ([file-io.md](file-io.md#2-saving)). New settings are added to this window when they are added to the config file.
- Keys: `j`/`k`/arrows move, `Tab` switches between groups and settings, `Enter` or `Space` toggles a boolean or opens a value picker or number prompt (on a group, `Enter` goes to its settings), `h`/`l` and `←`/`→` cycle choices and toggle booleans, `r` resets the focused setting to its default, typing `/` filters settings by name, `Esc` closes.
- **Value picker:** a finder like the theme picker, titled with the setting's name, over the window; the theme previews live as it is highlighted (§3). `Enter` keeps the value, `Esc` goes back.
- **Prompt:** numbers and the backup folder are typed on the window's status line, after the setting's name, with the standard text keys; `Enter` takes the value and `Esc` cancels. A number below its least (100 ms for the autosave delay, 1 copy kept) is refused with the reason, and the prompt stays open. An empty folder is the default one.
- **Filter:** `/` starts typing a filter on the status line; only groups and settings whose names hold it, ignoring case, are listed. `Enter` keeps it and gives the keys back to the settings, `Esc` clears it, `↑`/`↓` move while typing.
- Every change applies at once (theme, icons and word wrap repaint the whole UI behind the overlay; the autosave delay applies to the next save, and backups to the next copy) and is written to `config.toml` immediately (FR-SET-04). Resetting writes the default value, except for the backup folder, whose setting is removed. A failed write shows an error in the window, in place of the rule above its status line, and in the status line, and keeps the value for the session.
- A footer shows the config file's path, so people know where to edit by hand.

## 9. Animation (FR-UI-11)

Animation exists to show where focus landed, what a command changed and that an action was refused. It never makes the user wait. Research and sources: [reference/tui-animation.md](../reference/tui-animation.md).

### 9.1 Rules

- **Never in the way.** Every input is applied at once: state, layout, focus, scroll position and what the next key acts on change in the frame the input arrives (N-PERF-02). Effects are drawn over that final frame. Nothing waits for an effect to finish, and no input is queued, delayed or dropped because of one.
- **Cut short.** An input that changes a pane ends the effects running in it, drawn at their final frame. A new effect replaces a running one of the same kind on the same target.
- **Short and small.** 100–250 ms with an ease-out curve, except the status-message fade and the spinner. An effect covers only the cells it is about (a row, a pane body, the status line); only the theme crossfade covers the screen.
- **Frames only while needed.** While an effect runs, the UI redraws at up to 60 fps; with none running it requests no timer ticks (N-PERF-03). Processing effects fits in the N-PERF-02 frame budget.
- **Synchronized output.** Every frame, animated or not, is wrapped in synchronized output (DEC mode 2026, crossterm `BeginSynchronizedUpdate`/`EndSynchronizedUpdate`) so the terminal never shows half a frame. Terminals that do not support it ignore it.
- **Color depth.** Fades interpolate only between RGB colors. When the colors involved are ANSI or 256-color indexes, a flash shows its target style for its duration and then reverts in one step, and a fade is skipped. With `NO_COLOR`, flashes and fades are skipped; the status line still reports refusals.
- **Not animated:** single-step focus motion, scrolling of any kind (paging is not smooth-scrolled, since that would show offsets that are not final), typing and caret movement, entering and leaving edit mode, opening and closing pickers, the command palette, the context menu, the `?` panel and the sidebar, collapsing, closing or resizing panes, startup and quit. These must feel instant, and they are the most frequent actions.

### 9.2 Where the app animates

| ID | When | Effect | Duration | Reduced | Priority |
|---|---|---|---|---|---|
| UI-ANIM-01 | Focus **jumps**: any focus change other than a one-block motion, such as `gg`/`G`, page up/down, Go to Symbol, a sidebar entry, Move to, back/forward, zoom in/out, focusing another pane, or undo/redo moving focus. | Landing flash: the focused block's lines start with a faint accent-color background that fades out, leaving the gutter marker (D-30). | 250 ms | One-step flash | Must |

### 9.3 Setting

- `animations = "full" | "reduced" | "off"` in `config.toml` (FR-SET-01). It is listed in the settings window's Appearance group (§8), and Go to Command has commands to switch it; both write it back to the config. There is no key binding.
- **Full** runs everything in §9.2. The settings window shows the default that applies to the current session. **Reduced** keeps only the informational flashes as one-step flashes (UI-ANIM-01–03) and a static spinner; no fades or crossfades. **Off** draws no effects and a static spinner.
- Default: `full`, or `reduced` when the config does not set it and the session runs over SSH (`SSH_CONNECTION` or `SSH_TTY` is set), because every animation frame crosses the network.

### 9.4 Implementation

- `ui::animation` owns a tachyonfx `EffectManager` and applies effects to the buffer after the widgets render ([architecture.md](architecture.md)). Effects are keyed by kind and target so a new one replaces the old.
- The core has no animation state, timing or durations (code-quality.md, UI-independent core). The UI derives triggers by comparing the view state before and after each update (focus, pane roots, fold state, theme), plus two facts the core reports: the blocks the last change touched, and that the last intent was refused.
- Effects advance by the elapsed time the event loop measures between frames, and tachyonfx output depends only on that time, so tests drive animations with a fixed clock.
- Tests: UI tests render through `TestBackend` at chosen elapsed times. They check that each effect's final frame equals the frame drawn with animations off, that input during an effect takes effect in the same frame, that no ticks are requested when nothing runs, and each fallback in §9.1. Tests not about animation use `off`.
