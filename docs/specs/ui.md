# Spec: Screen layout and styling

Covers FR-BLK display, FR-TAG display, FR-FMT-01, FR-KEY-04–06, FR-UI-05–11, FR-SET-02–03, N-PORT-02 and N-PORT-04.

- **Panes** (FR-UI-02) across the screen as columns, each with a breadcrumb header (its first row, a house icon `⌂` for the document root followed by the path to the zoom block, D-32, starting after the focus gutter of §2 so the root crumb lines up with top-level blocks, D-35) or, in a special view, that view's icon and name in its place, such as the Today icon and `Today` ([navigation.md §7](navigation.md#7-today-view-fr-tag-04-d-7)) separated from the outline by a dim horizontal rule, like Workflowy (D-29), and, when zoomed, a title row showing the zoom block styled as in §2 for its type (marker, color, dimming, a project's `:`), in bold and without indent, so its type is clear (D-34). While there is more than one pane, each header ends in the pane's number, the one `Alt+N` and `gN` focus, in the dim text color, right-aligned a column inside the pane's right edge, the breadcrumbs cut off a space before it (D-116). Panes are separated by a dim vertical rule; only the focused pane shows its focus marker (§2), and the other panes' breadcrumbs are dimmed, so the focused pane's header stands out.
- **Status line** at the bottom: mode, file path (marked when it is a `/tmp` file not yet saved elsewhere), save state or error, pending key prefix, transient messages. The path reads the home folder as `~`. When the line is too narrow, the path gives up its room first: it keeps as much of its end as fits behind `…`, down to the `…` alone, so the save state and messages stay in view. A pending key prefix stands at the line's right end and the rest of the line gives up its room to it, the path first, so it never covers a message. A conflict copy's path in a message reads the home folder as `~` too and likewise gives up its start first, so its file name stays longest; a message that still does not fit ends in `…`.
- **Secondary sidebar** on the right, 32–40 columns, shown only while it holds the `?` shortcuts panel (§4) (D-28, D-66). It takes its width from the panes, which keep their minimum and scroll horizontally as in [navigation.md §5](navigation.md#5-panes-fr-ui-02--fr-ui-04-d-13). Below 80 columns it is drawn over the right part of the focused pane.
- **Navigator** (FR-UI-01, D-79), the window `Ctrl+G` opens: a box centered over the panes below their headers, as wide as it can be up to 48 columns and as tall as its lines up to the room there, its border and title "Navigator" in the accent color like the finders, the filter typed into it in its bottom border as the context menu has its own (D-86), scrolling to keep its focused entry in view. Inside, after a gutter like the outline's: the inbox (D-75) and the special views' entries, Today, Upcoming, Overdue, Colors, Logbook, Starred and Flagged, one per line with no blank line between them, each but Today unless its setting is off (D-80, D-92, D-93, D-102), then a blank line and the bookmarks, each its text alone, under a Bookmarks heading, then a blank line and the project tree under a Projects heading; a section without entries has no heading, and the first line is never blank (D-77), as when a filter leaves Today out (D-86); a filter that leaves no entries shows a dimmed line saying nothing matches. The headings, bookmarks and top-level projects start in the same column, projects 2 columns more per level, each right behind its fold marker, which for a top-level entry stands in the gutter (D-60, D-61, D-68). A project with open tasks shows their count, as a collapsed block counts them (§2, D-67), sub-projects included, dimmed and right-aligned a column inside the right border, its text cut off one space before the count; and so do bookmarks, counted the same way, and the special views, each counting the open tasks it lists (D-85); an entry with none shows no number (D-73). The focused entry is marked like the outline's focused block (§2); the entry of where the focused pane is, when the focus is elsewhere, gets a selected block's dimmed marker (D-68).
- **Pickers and prompts** (Go to Symbol, Go to Project, Go to Command, Move to, type, color, Save As) are centered overlays at most 80×20; the finders (Go to Symbol, Go to Project, Go to Command, Move to) have their border and title in the accent color, like the command menu.
- **Date prompt** (`ms`/`md`, D-54): a panel across the full width just above the status line, a bordered box titled with the date it sets, its border and title in the accent color, holding the typed text and the preview below it. While it is open the outline gives up its rows, scrolling only if the focused block would otherwise be under the panel, and everything else on screen (breadcrumbs, outline, status line) is dimmed with the terminal's dim attribute.
- **Quick Add** (`qq`, D-96): a panel placed and dimming as the date prompt does, titled `Quick Add` and its destination's path, holding the text behind a task's marker while it is a task, with the dates that count highlighted in the start and due chip colors, and below it what `Enter` would do; its project picker is a finder drawn just above it, its border and title in the accent color, or over the panel too when the rows above the panel cannot hold the picker's border, filter and one entry, so it lists a project on any screen with 4 rows above the status line ([editing.md §6](editing.md#6-quick-add-fr-mode-07-fr-mode-08)).
- **Dialogs dim the screen behind them** (D-69): while a dialog that takes the keys is open (the Navigator, the finders, the theme chooser, the type and color pickers, the Edit Node dialog and its parent finder, the context menu, Save As, the settings window and its value picker, the date prompt, Quick Add and the conflict prompt), everything drawn behind it, the panes, shortcuts panel and status line included, takes the terminal's dim attribute, as for the date prompt; the dialog itself does not. The attribute keeps every color, so it reads the same in every theme and color depth. The edit-mode command menu and the shortcuts panel are not dialogs: the text being typed and the outline stay as they are.
- Below 40×10 only the focused pane and the status line are drawn.
- A wide character (CJK, emoji) that a popup, a panel or the screen's edge covers in part is hidden whole, so no grapheme is split and the popup's edge shows (N-PORT-04).

## 2. Blocks

Each row: indent, then the marker (if the type has one) and a space, then text, the star and bookmark icons, and right-aligned chips. The indent is exactly the block's depth in the hierarchy, 2 columns per level, whatever its type; markers and icons come after it and never change it. Only tasks have markers; every other block starts with its text. So a task's text node, being its child, sits one level in and lines up with the task's text, as in TaskPaper (D-31).

An entry of the Today view has no indent and shows its breadcrumb path dimmed after its icons, two spaces after them, the crumbs joined by ` › ` ([navigation.md §7](navigation.md#7-today-view-fr-tag-04-d-7)).

The other special views draw their entries the same way. A grouped view draws each group's heading on a line of its own above the group's first entry, with no indent, in bold, and a blank line above every heading but the first; the heading is not a row the focus can reach ([navigation.md §7.1](navigation.md#71-other-special-views-fr-tag-07-d-80), D-80).

| Block (FR-BLK) | Marker | Text |
|---|---|---|
| Project | none | bold heading in the primary color (Textual's `$primary`), ending in `:` as in the file |
| Task | `-`, done `✔` | normal; done tasks dimmed and struck through (falls back to dim), their `✔` dimmed too (D-36) |
| Text | none | slightly dimmed; less dim than done tasks and the other dimmed blocks (D-37). It is the theme's dim-text color (§3). A line carrying `@code` is text like any other (D-43) |
| Section (a text block with `@section`, D-52) | none | bold italic label in the headers color (Textual's `$secondary`, D-49), no rule; children indented below |
| Divider (a text block reading `---`, D-52, or `---Title---`, D-76) | none | in navigate mode a horizontal rule across the pane in the rule-lines color, dimmed further so it is fainter than the header rule (D-33); a titled divider's title sits in the middle of the rule in the text style, a space either side, followed by its icons and fold marker; while edited, its raw text in the text style |

- Tasks (normal text), projects and sections (their own colors) stand out; every other block type is dimmed (D-29).
- **Completed blocks** (FR-DONE-01, D-40): any block can be done. A done block keeps its type's marker and color and is dimmed and struck through (falls back to dim), its marker dimmed with it; a done task's marker is `✔` (D-36). Every block inside a done block, at any depth, is dimmed, marker included, but not struck through, since only the done block carries `@done`. The same holds when zoomed: the title row and the rows below it are dimmed when the zoom block or a block above it is done. A divider is already very dim and its rule looks the same when done; a titled divider's title is dimmed and struck through like any text (D-76). The breadcrumb header keeps its style; the title row shows the zoom block's state.
- No fold marker is shown on expanded blocks, since any block can be folded. A block that has children and is collapsed shows `▸ n` after its text and icons, projects included (D-29), where `n` counts the open tasks it hides: every task at any depth below it that is neither done nor inside a done block, so projects, notes, sections and dividers never count, and a collapsed block that is done or inside a done block hides none. With no open tasks hidden it shows `▸` alone (D-67).
- **Tags are never shown** (FR-TAG-01). Their effects are: dates as compact chips (`󱙬 tomorrow`, FR-TAG-03, D-46), a note and comments as attachment icons dimmed in the headers color at the right of the row before the date chips, the comments icon with their count ([attachments.md §2](attachments.md#2-display-fr-att-02), D-94, D-109, D-110), `@flag` as a red flag (`󰈻`, `⚐` without Nerd Font icons), `@star` as a star and `@bookmark` as a bookmark icon right after the text, a space before each, in that order, all dimmed with a done block like the date chips and not shown on the block being edited (FR-TAG-04, FR-TAG-12, D-47, D-91), and a color tag tints the row's background with a very dim shade of its color, from the block's marker to the pane's right edge, leaving the indentation and every text color and style as they are (FR-TAG-05, D-48, D-91). Bookmarks are also listed in the Navigator.
- **Date chips** (FR-TAG-03, D-46): right-aligned at the end of the row, the start date before the due date, each a calendar icon (§7) and the date named relative to today's local date: `today`, `tomorrow`, `yesterday`; the weekday (`Tue`) 2 to 6 days ahead; `next Tue` 7 to 13 days ahead; `in 15 days` further ahead; `3 days ago` further back. Start chips are green and due chips red. A due date before today's local date is overdue, unless the block is done or inside a done block, whose chips are dimmed with it; an overdue chip has its own icon and is bold and reversed. A tag whose value is not a date shows no chip. The block being edited shows none. Chips sit on a block's first line, and its text stops before them: it wraps, or with wrap off ends in `…` (FR-UI-05). Chips follow the local date: the screen is redrawn at local midnight while a date chip is shown.
- **Inline formatting** (FR-FMT-01): `**bold**` renders bold and `` `code` `` dimmed, both in the block's own color (D-49), with the markers hidden in navigate mode; edit mode shows the markers.
- **Links** (FR-BLK-06, FR-FMT-03, D-45), in every block and in navigate mode only; edit mode shows the raw text: bare `http(s)://` URLs, `<url>` and `[title](url)` show their title (or URL) in the link style, underlined in the links color over the block's own style, and hide `[`, `](url)`, `<` and `>`. A line carrying `@url(…)` draws its whole title in the link style, its tag hidden like any other.
- **Markdown headings in text blocks**, sections included (FR-FMT-03, D-52, [editing.md §2.2](editing.md#22-markdown-in-text)), navigate mode only; edit mode shows the raw text: headings hide their `#` markers. Level 1 is bold and underlined, levels 2 to 6 bold, all in the text block's own color (D-49). Heading rows keep the block's indentation and get no rule, so they never look like a section.
- **Focus and selection**: the focused block is marked by a `▌` (a half block) in a 2-column gutter left of the outline, on its line (D-30): in the primary color (Textual's `$primary`) in navigate mode and in the accent color (Textual's `$accent`) while editing, so the marker shows the mode (D-51). That line, gutter included and across the pane's full width, also gets the current-line background, a step brighter than the normal one, in navigate and edit mode alike; it changes no text color or style, so dimmed, done and colored blocks look the same as unfocused (D-39). On a block whose color tag tints its row, a step brighter shade of its tint takes the band's place from the marker to the right edge; the gutter and indentation keep the band (D-48). The colors are the theme's (§3). Selected blocks get the same `▌`, in the primary color dimmed, so focus and selection line up as one bar (D-51).
- **Edit mode**: the focused block's text becomes a one-line inline editor at the same position, with a visible caret and the markers shown (FR-MODE-02). Text wider than the pane scrolls only as far as keeps the caret in view ([editing.md §2](editing.md#2-edit-mode)).
- **Tabs inside text** show as one space in both modes, in a titled divider's title, in the entries and paths of the finders and the Navigator, and in the breadcrumbs, a view entry's path and the Quick Add title, so the words they separate stay apart; the file keeps the tab.
- **Wrap** (FR-UI-05): on, long text wraps under its start column; off, every block takes one row and overflowing text ends in `…`, cut before the flag, star and bookmark so they stay in view while there is room for them. Off by default (D-89); `word_wrap = true` in `config.toml` turns it on, and the settings window (§8) changes and keeps it; `Alt+z`/`gw` toggles it for the session. Lines break between words, inside a word only when it is wider than a line, and never at the spaces they break at. A block indented so deep that no column is left for its text takes one row ending in `…`, as with wrap off. Every line of a wrapped block gets its focus marker, band and tint, and scrolling keeps all of the focused block's lines in view, or its first lines when it is taller than the pane. When lines reflow (toggling wrap, resizing, narrowing or widening a pane, the `?` panel opening), each pane keeps the same top row (owner, 2026-10-06). The block being edited takes one line (edit mode above). Widths use `unicode-width`; graphemes are never split.

## 3. Themes (FR-UI-06–08)

- Built-in themes: **Terminal Dark**, which uses the terminal's 16 ANSI colors (so it follows the user's palette) and the 256-color grey 248 for notes and dark shades of the 256 colors for row tints (D-119), with the 256-color grey 255 for text on the focused row's band and on those tints, so they read on a light palette too (D-125), plus the twelve truecolor themes of FR-UI-08 ([palettes](../reference/themes.md)), used only when `COLORTERM` indicates support (`truecolor` or `24bit`). There is no light 16-color theme (D-63).
- With truecolor, tpt asks the terminal at start for its text color, background and 16 ANSI colors (OSC 10, OSC 11 and OSC 4), ending with a primary device attributes query (DA1), whose answer every terminal sends after the others, and waits for it a second at most, before anything reads keys. When the terminal reports its text color and background, Terminal Dark is drawn in the RGB colors it reported: the terminal's own colors as reported, each ANSI color as reported or, when not reported, as it is, and the 256 colors' greys and cube as xterm defines them. It looks the same, and its fades run (§9.4). A terminal that does not report them, or no truecolor, keeps Terminal Dark in the terminal's colors (D-128).
- A theme defines colors for: text, dim text, primary, accent (the focus marker while editing, D-51), selection, focus, current line (the background of the focused block's lines, D-39), headers, rule lines, links, each of the six tag colors and its row tints, plain and focused (D-48), start and due chips, overdue, errors. A truecolor theme also gives the screen its text color and background; Terminal Dark keeps the terminal's, as reported when it reported them (D-128). Every theme's dim text differs from its text color and is never a color terminals draw as their default foreground, so notes are dimmed everywhere (D-37, D-63).
- `theme = "<name>"` in `config.toml` chooses the theme, by the name [reference/themes.md](../reference/themes.md#names-and-roles) gives it, such as `nord`; anything else is reported once (FR-SET-04). Default: Terminal Dark (D-63).
- A truecolor theme in a terminal without truecolor, light or dark, is drawn as Terminal Dark, so every theme is usable in 16 colors (N-UX-03, D-63); the choice is kept, and shows in full once the terminal has truecolor. Meanwhile the theme picker says so dimmed in its bottom border, "No truecolor here: themes show as Terminal Dark", or with `NO_COLOR` set "NO_COLOR is set: themes show no colors", and the settings window gives the same words as the Theme setting's description and in its theme picker (D-127).
- **Choose Theme** in Go to Command opens the theme picker: a finder like Go to Command, titled "Theme", listing the built-in themes with the one in use highlighted. It previews each theme live as it is highlighted, by typing or arrows; `Enter` keeps it and saves it to the config (OQ-18, FR-SET-04), `Esc` restores the previous one. A save that fails is reported in the status line, and the theme is kept for the session.
- `NO_COLOR` set (and not empty): no colors, only bold, dim, italic, underline, strikethrough and reverse.
- Unicode markers have ASCII fallbacks (`v`, `>`, `[x]`, `-`, `~` for `⌂`) when the locale is not UTF-8.
- The settings window (§8) previews themes live in the same way.

## 4. Shortcuts panel (FR-KEY-04)

`?` toggles a panel in the secondary sidebar on the right (§1, D-28), listing the most useful bindings for the current mode and context (navigate, edit, Navigator, picker, and the Edit Node dialog, Quick Add and the date prompt, which type the outline's keys as text), grouped as in [keybindings.md](keybindings.md) and showing user overrides. A list taller than the panel scrolls (D-55): `)` and `(` scroll it down and up a page in navigate mode, while the panel stays open and every other key keeps its binding; a dim `↑ more` line first and `↓ more` line last show that lines are hidden above or below, each with the key that scrolls that way when that key would scroll, so not while editing, in the Navigator or in a popup. The panel opens at the top. It notes when `Alt` keys have never been received (macOS Option setting) and whether the kitty keyboard protocol is active.

## 5. Context menu (FR-KEY-06)

A popup anchored at the focused element (or at the pointer for right-click) listing every command available for that element, grouped (Edit, Structure, Metadata, View, Panes), each with its key binding right-aligned. Commands that do not apply (for example Open URL on a block without one) are omitted. Entries come from the core's command list for that context, so the menu, the command palette and the `?` panel always agree.

- **Look:** the command menu's box below (title "Commands:", icons, a dim line between groups), placed like it below the focused row from the start of its text, or below the Navigator's focused entry, with each command's keys in the primary color at the right and the filter, as typed, in the bottom border.
- **On a block:** Edit, Edit Node, the new-block commands, the clipboard, Duplicate and Delete; the structural commands; status (Complete or Uncomplete, Toggle Star, Bookmark or Remove Bookmark); dates; colors; Convert Type with Make or Remove Section; then Zoom In, Toggle Fold for a block with children, Count and Open Link for a block with a link; then the Panes group: Open in New Pane, Open Location in New Pane and, while there are other panes, Close Pane. Labels and omissions follow the block's state as in the command menu.
- **On the selection:** the same groups without the commands of one block (editing it, adding blocks, the type picker and the view group), labelled for every selected block: Uncomplete only when all are done, Clear Due Date when any has a due date.
- **In a special view:** what the view does not take (adding, pasting, indenting, moving, folding, and Move Up and Move Down outside Today) is left out (navigation.md §7, §7.1).
- **On a Navigator entry** (while the Navigator is open): Go to Entry, Open in New Pane, Collapse or Expand Entry for a project entry with child projects, then Return to Outline, which closes it.
- **On a crumb** (right-click only, since crumbs take no keyboard focus): Zoom Here, or Go Home on `⌂`, unless the pane is there, and Open in New Pane; then Open Location in New Pane and, while there are other panes, Close Pane.
- **On a pane header** (right-click only, outside the crumbs or in the Today view): Zoom Out while zoomed and Go Home away from home; then the Panes group as on a crumb.
- Typing a character that would match nothing is not added to the filter; `Backspace` on an empty filter does nothing.

The command menu of edit mode ([editing.md §2.3](editing.md#23-command-menu), D-50) is a smaller popup of the same kind: a bordered box titled "Commands:", its border and title in the accent color (D-54), on the line below the caret, starting at the caret's column, or above the caret's line when there is no room below, moved left to stay on screen. It is as tall as its entries but no taller than the larger room below or above the caret's line, and scrolls to keep the highlighted entry in view. It lists the matching labels one per line, each after its icon (§7) and padded by 2 columns on each side, the highlighted one reversed, with a dim line across the box between groups, and shows `/` and the filter in its bottom border once one is typed.

## 6. Mouse (FR-KEY-05, D-16)

- Click a block: focus it (navigate mode); click inside the text of the block in edit mode: place the caret.
- Click a fold marker: toggle fold. Click a crumb: zoom the pane there. Click a Navigator entry: go there. Click a pane header: focus that pane.
- Alt+click a block, an internal link (once links exist, FR-OPS-10) or a crumb: open it in a new pane.
- Right-click a block, the selection, a Navigator entry, a crumb or a pane header: open its context menu (FR-KEY-06).
- Wheel: scroll the pane under the pointer without moving focus, 3 lines a step, no further than the first and last lines; the pane stays where the wheel left it until the next key or click, which bring the focus back into view as any motion does. Over the `?` panel the wheel scrolls the panel (D-55). While the Navigator is open the wheel does nothing, over it or the panes behind it, as behind any dialog.
- A block's row counts from the gutter to the right edge. A click on a block of another pane, a crumb or a pane header gives that pane the keys first, and any click outside the open Navigator closes it first (D-79). A right-click on a block that is not selected clears the selection and focuses the block, so the menu is the block's; on a selected block it opens the selection's menu. A click on the `▸`/`▾` of a Navigator project entry folds or unfolds it and focuses that entry.
- While a popup, picker, prompt or the conflict prompt is open, the mouse does nothing.
- Moving the pointer, dragging, releasing a button, the middle button and the sideways wheel do nothing, and the event loop drops them so they draw no frame.
- No feature depends on the mouse; every action above has a key.

## 7. Icons (FR-UI-09, FR-UI-10)

- `icons = "nerd"` (default) draws Nerd Font glyphs; `icons = "none"` draws the Unicode markers of §2. When the locale is not UTF-8, both settings draw the ASCII fallbacks of §3.
- Every icon has exactly one fallback, defined next to it in one table in `ui::theme`, with its ASCII form, so the sets cannot drift. Icons are drawn only by the UI; the core reports types and states, never glyphs. The locale is UTF-8 when the first of `LC_ALL`, `LC_CTYPE` and `LANG` that is set says so; with none set it is not. The table holds: the breadcrumb root `󰋜` (`⌂`, ASCII `~`), a Navigator project's fold `▾` (ASCII `v`) and `▸` (`>`), which also marks a collapsed block's count, and the task markers `-` and `✔` (ASCII `[x]`), these four the same with Nerd Font icons as without (D-59, D-60), the status line's navigate `󰆿` (`↕`) and edit `󰏫` (`✎`) modes and unsaved mark `󰧞` (`●`); the date chips' start `󱙭` (fallback `↦`), due `󱙬` (`⇥`) and overdue `󰨱` (`!`) (D-46), the note `󱇗` (`≡`, ASCII `n`) and comments `󰆉` (`❞`, ASCII `c`) icons, dimmed in the headers color at the right of a block's row before its date chips, the comments icon with their count ([attachments.md §2](attachments.md#2-display-fr-att-02), D-94, D-106, D-109, D-110), which also mark the attachments panel's section headings, Open Note and Open Comments and their settings, the `@flag` flag `󰈻` (`⚐`) after a block's text, in red (D-91), and the `@star` star `󰓎` (`★`) and the bookmark `󰃀` (`⚑`) after it (D-47), which also mark the command menu's date, Toggle Flag, Toggle Star and bookmark entries, the star also Display starred items in Today view (D-88); the Today view's sun `󰖙` (`☼`, ASCII `O`) in the Navigator's Today entry (D-68), its header and Go to Today (D-88), the Navigator's inbox tray `󰚇` (`⊔`, ASCII `I`) before the INBOX project (D-75), also marking its setting and Quick Add to Inbox, as the sun marks Show Today in Navigator (D-77, D-88), Special handling of TODAY project and Quick Add to Today (D-98), Quick Add marked by a plus `󰐕` (`+`), a date entry's icon green or red like its chip. The command menu's other entries (D-54) are project `󰉖` (`▸`), task `󰄱` (`☐`), note, for Note and Remove Section, `󰦨` (`¶`), Make Section `󰚟` (`§`), Complete and Uncomplete `󰗡` (`✓`), the color entries `󰏘` (`●`), each in its color, as the Colors view's group headings also show it (D-83), Edit Node the edit mode's pencil `󰏫` (`✎`), Open Link `󰌷` (`↗`), Duplicate `󰆏` (`⧉`), Delete `󰧧` (`✕`), and `󰅂` (`›`) for any command without an icon of its own. The finders show each block's type icon (project, note, section), a task's marker, `-` or `✔`, as the outline draws it (D-70), and Move to's Home the root's; Go to Command shows the command menu's icons and the animation icon `󰗘` (`≈`, ASCII `a`) on the Animations commands, Go to Today the sun, Go to Project the project icon, Open Settings a cog `󰢻` (`⚙`), the type picker its types' and the color picker the color icon in each color. The settings window marks its settings: the theme with the color icon, icons `󰠲` (`◇`), word wrap `󰖶` (`↩`), animations `󰗘` (`≈`), the autosave delay `󰔛` (`◷`), backups and backups kept `󰁯` (`↺`) and the backup folder `󱂀` (`▭`).
- Icons cover: the breadcrumb root (`⌂`), project fold state, a collapsed block's fold marker and open-task count, date chips (start, due, overdue), color tags, the note and comments attachments, the `@flag` flag, the `@star` star, bookmarks, the Today view's sun, the status line's mode and save state, and the entries of pickers, the context menu and the settings window.

Starred (D-92) the star that marks a starred block (D-88). Flagged (D-93) the red flag that marks a flagged block (D-91).

## 8. Settings window (FR-SET-02, FR-SET-03)

- Opened with `g,` in navigate mode or **Open Settings** in Go to Command; a centered overlay like the pickers, but up to 100×30, its border and title in the accent color like the finders.
- Left column: groups (Appearance, Editing, Files); a group shows once it has a setting, so Editing is left out until one exists. Right: that group's settings, two lines each: a `*` when the value differs from the default (the value is then bold too), the setting's icon (§7), its name and, at the right, its current value; below, a one-line description, dimmed. The highlighted group or setting is reversed in the column that has the keys; the highlighted group is bold in the primary color while the settings have them.
- Settings in v1: Appearance — theme (FR-UI-06), icons (§7), word wrap (FR-UI-05), special handling of the INBOX project (`special_inbox`, on by default, [navigation.md §6](navigation.md#6-navigator-fr-ui-01-d-7-d-11-d-28-d-79), D-75), special handling of the TODAY project (`special_today`, on by default, [editing.md §6](editing.md#6-quick-add-fr-mode-07-fr-mode-08), [navigation.md §7](navigation.md#7-today-view-fr-tag-04-d-7), D-98, D-102), Display starred items in Today view (`today_starred`, on by default, D-88), Show Upcoming, Overdue, Colors and Logbook in Navigator (`sidebar_upcoming`, `sidebar_overdue`, `sidebar_colors`, `sidebar_logbook`, each on by default, each with its view's icon, D-80), Show Starred in Navigator (`sidebar_starred`, on by default, with the star, D-92), Show Flagged in Navigator (`sidebar_flagged`, on by default, with the flag, D-93), Use Notes Attachments and Use Comments Attachments (`attachments_notes`, `attachments_comments`, each on by default, with its icon, [attachments.md §6](attachments.md#6-settings-fr-att-06), D-94), animations (§9), Weather animation (`weather`, on by default) and Weather after idle (`weather_idle_minutes`, in minutes, 3 by default, least 1) (§10); Files — autosave delay and backups: on/off, folder, number kept ([file-io.md](file-io.md#2-saving)). New settings are added to this window when they are added to the config file.
- Keys: `j`/`k`/arrows move, `Tab` switches between groups and settings, `Enter` or `Space` toggles a boolean or opens a value picker or number prompt (on a group, `Enter` goes to its settings), `h`/`l` and `←`/`→` cycle choices and toggle booleans, `r` resets the focused setting to its default, typing `/` filters settings by name, `Esc` closes.
- **Value picker:** a finder like the theme picker, titled with the setting's name, over the window; the theme previews live as it is highlighted (§3). `Enter` keeps the value, `Esc` goes back.
- **Prompt:** numbers and the backup folder are typed on the window's status line, after the setting's name, with the standard text keys; `Enter` takes the value and `Esc` cancels. A number opens selected, so typing replaces it. A number below its least (100 ms for the autosave delay, 1 copy kept), or above 4294967295, is refused with the reason, and the prompt stays open. An empty folder is the default one.
- **Filter:** `/` starts typing a filter on the status line; only groups and settings whose names hold it, ignoring case, are listed. `Enter` keeps it and gives the keys back to the settings, `Esc` clears it, `↑`/`↓` move while typing.
- Every change applies at once (theme, icons, word wrap and the INBOX setting repaint the whole UI behind the overlay; the autosave delay applies to the next save, and backups to the next copy) and is written to `config.toml` immediately (FR-SET-04). Resetting writes the default value, except for the backup folder, whose setting is removed. A failed write shows an error in the window, in place of the rule above its status line, and in the status line, and keeps the value for the session.
- A footer shows the config file's path, so people know where to edit by hand, as the status line shows a path: the home folder as `~`, and when it is too long, as much of its end as fits behind `…` (§1). In a narrow window a setting's name, a description and the keys on the status line end in `…` where they are cut, and a name is cut short of its value, a space before it.

## 9. Animation (FR-UI-11)

Animation exists to show where focus landed, what a command changed and that an action was refused. It never makes the user wait. Research and sources: [reference/tui-animation.md](../reference/tui-animation.md).

### 9.1 Rules

- **Never in the way.** Every input is applied at once: state, layout, focus, scroll position and what the next key acts on change in the frame the input arrives (N-PERF-02). Effects are drawn over that final frame. Nothing waits for an effect to finish, and no input is queued, delayed or dropped because of one.
- **Cut short.** An input that changes a pane ends the effects running in it, drawn at their final frame. A new effect replaces a running one of the same kind on the same target.
- **Short and small.** 100–250 ms with an ease-out curve, except the status-message fade and the spinner. An effect covers only the cells it is about (a row, a pane body, the status line); only the theme crossfade covers the screen, apart from the weather (§10).
- **Frames only while needed.** While an effect runs, the UI redraws at up to 60 fps; with none running it requests no timer ticks (N-PERF-03), apart from the single timer that starts the weather (§10). Processing effects fits in the N-PERF-02 frame budget.
- **Synchronized output.** Every frame, animated or not, is wrapped in synchronized output (DEC mode 2026, crossterm `BeginSynchronizedUpdate`/`EndSynchronizedUpdate`) so the terminal never shows half a frame. Terminals that do not support it ignore it.
- **Color depth.** Fades interpolate only between RGB colors. When the colors involved are ANSI or 256-color indexes, a flash shows its target style for its duration and then reverts in one step, and a fade is skipped. With `NO_COLOR`, flashes and fades are skipped; the status line still reports refusals.
- **Not animated:** single-step focus motion, scrolling of any kind (paging is not smooth-scrolled, since that would show offsets that are not final), typing and caret movement, entering and leaving edit mode, opening and closing pickers, the command palette, the context menu, the `?` panel and the Navigator, collapsing, closing or resizing panes, startup and quit. These must feel instant, and they are the most frequent actions.

### 9.2 Where the app animates

| ID | When | Effect | Duration | Reduced | Priority |
|---|---|---|---|---|---|
| UI-ANIM-01 | Focus **jumps**: any focus change other than a one-block motion, such as `gg`/`G`, page up/down, Go to Symbol, a Navigator entry, Move to, back/forward, zoom in/out, focusing another pane, or undo/redo moving focus. | Landing flash: the focused block's lines start with a faint accent-color background that fades out, leaving the gutter marker (D-30). | 250 ms | One-step flash | Must |
| UI-ANIM-02 | A command changes blocks other than just the focused one: paste, duplicate, Move to, an operation on a multi-block selection, undo, redo, or a reload after an external change (F-FILE-06). | Change highlight: every visible changed row is tinted in the accent color, fading out. | 250 ms | One-step flash | Must |
| UI-ANIM-03 | The core reports an intent as refused, such as typing `@` at the start of a word ([editing.md](editing.md)). Commands the specs define as no-ops are not refusals. | Error flash on the focused row, alongside the intent's status message when it has one. | 150 ms | One-step flash | Must |
| UI-ANIM-04 | A block is completed or uncompleted. | The new style (check mark, dim, strikethrough, and the dimming of the blocks inside it) applies at once; the text color eases from the old style to the new. When completed blocks are hidden, the block disappears at once with no exit effect. | 200 ms | None | Should |
| UI-ANIM-05 | A pane's root changes (zoom in/out, go home, back/forward) or a pane opens. | The pane body fades in from the background, from the top row down; the new last crumb gets a landing flash. | 120 ms | None | Should |
| UI-ANIM-06 | A block is expanded. | The newly shown rows fade in. | 120 ms | None | Should |
| UI-ANIM-07 | A transient status message reaches the end of its display time. | It fades out instead of vanishing; the UI keeps a copy of the message to draw while it fades. | 300 ms | Vanishes | Should |
| UI-ANIM-08 | The user waits longer than 300 ms on an operation, such as opening a large file, reloading or Save As. | A spinner in the status line until it finishes. | While waiting | Static `…` | Must |
| UI-ANIM-09 | The previewed theme changes, in the theme picker (FR-UI-06) or the settings window (§8). | Crossfade from the old theme to the previewed one when both are drawn in RGB colors; otherwise instant. | 150 ms | None | Should |

### 9.3 Setting

- `animations = "full" | "reduced" | "off"` in `config.toml` (FR-SET-01). It is listed in the settings window's Appearance group (§8), and Go to Command has commands to switch it; both write it back to the config. There is no key binding.
- **Full** runs everything in §9.2. The settings window shows the default that applies to the current session, and resetting the setting there writes that default. **Reduced** keeps only the informational flashes as one-step flashes (UI-ANIM-01–03) and a static spinner; no fades or crossfades. **Off** draws no effects and a static spinner.
- Default: `full`, or `reduced` when the config does not set it and the session runs over SSH (`SSH_CONNECTION` or `SSH_TTY` is set), because every animation frame crosses the network.

### 9.4 Implementation

- `ui::animation` owns a tachyonfx `EffectManager` and applies effects to the buffer after the widgets render ([architecture.md](architecture.md)). Effects are keyed by kind and target so a new one replaces the old.
- The core has no animation state, timing or durations (code-quality.md, UI-independent core). The UI derives triggers by comparing the view state before and after each update (focus, pane roots, fold state, theme), plus two facts the core reports: the blocks the last change touched, and that the last intent was refused.
- Effects advance by the elapsed time the event loop measures between frames, and tachyonfx output depends only on that time, so tests drive animations with a fixed clock.
- Choices the table leaves open:
  - A one-block motion is a focus change to a block next to the old one, in the rows shown before or after it, within the same pane and location (`j`/`k`, arrows, a sibling step to an adjacent row). Any other focus change, including a click on a far block, is a jump.
  - The change highlight runs when the changed blocks include any but the focused one, or, in navigate mode, after paste, duplicate, Move to, undo, redo or a reload, so a single pasted or restored block is highlighted too. A moved block counts with everything inside it, so indenting or moving a parent tints its children. Removed blocks leave nothing to tint.
  - A reload's changed blocks are the blocks whose depth and text are new in the reloaded outline.
  - Refusals are the read-only notice, the typed-tag hint, a failed edit and a refused Keep theirs. Hints that a command has nothing to act on are not refusals.
  - Flashes tint the cells' background 30% of the way toward the accent or error color, over a block's own lines and not the heading of its group in a special view (D-80). A block that both the landing flash and the change highlight cover is tinted once, not twice. They are drawn only over panes shown whole, not over one cut off at a narrow screen's edge.
  - The spinner sits at the right end of the status line and covers saves, Save As and conflict copies, whose results always come back. File checks for a reload and backups run unwatched, since a check of a file that cannot be read and a backup that succeeds report nothing. A file is opened before the first frame, so opening shows no spinner.
  - Fades (UI-ANIM-04–07, 09) need the theme's text and background to be RGB colors, so Terminal Dark, the default, shows them only on a truecolor terminal that reported its colors (§3, D-128), and 16-color terminals show none of them.
  - Completing or uncompleting eases the text of every row of the pane with the keys whose dimming changes: the block and the blocks inside it. The check mark and strikethrough apply at once; each cell whose text color or dimming changes eases from how the frame before drew it, so the focus marker and what is dimmed either way keep their look; while it eases, dimmed text is drawn up to half way toward its background, and the terminal's own dim takes over at the end.
  - A pane's root changes whenever it shows another place: zooming, going home, back and forward, a Navigator entry or a special view, and a pane opening. Its rows fade in one after another from the top, the first done half way through and the last starting there. The last crumb, or a special view's name, gets the landing flash.
  - The expand fade covers the rows of the pane with the keys that an expand command shows (the keys, the context menu or Go to Command, a click on `▸`); showing completed blocks is not an expand.
  - A status message fades by moving its text color to the background; a new message replaces it at once.
  - The theme crossfade runs whenever the theme drawn changes while the theme picker or the settings window is open, including `Esc` going back and changing the theme in place in the settings window; `Enter` keeps the theme shown, so it does not fade.
- Tests: UI tests render through `TestBackend` at chosen elapsed times. They check that each effect's final frame equals the frame drawn with animations off, that input during an effect takes effect in the same frame, that no ticks are requested when nothing runs, and each fallback in §9.1. Tests not about animation use `off`.

## 10. Weather (FR-UI-12)

A decorative animation of the season's weather plays over the whole screen while the app sits idle, and ends at the next input (D-129).

### 10.1 When it plays

- **Start:** when no input has arrived for the idle time, `weather_idle_minutes` (3 by default), in any mode and with any window, picker or prompt open. Input is any key, paste, mouse event the app receives, or resize. A file reload, an autosave, a status message timing out or anything else the app does by itself is not input: it neither delays the start nor ends the weather.
- **Start Weather Animation** in Go to Command starts it at once, whatever the setting and the idle time say, as long as there is weather this season.
- **End:** the first input ends it at once, with no exit effect, and that input does nothing else: a key is not applied, a click does not focus or open anything, a paste is dropped, a resize lays the app out at the new size. The app is then as it was before the weather started, apart from what changed by itself meanwhile, and the idle time counts again from that input.
- **Not at all:** with `weather = false`, or unless `animations` is `full`, as it is by default except over SSH, where it is `reduced` (§9.3); `animations = "full"` set in the config over SSH plays it. The command still starts it in all these cases, since it is asked for.
- **Season** by the local date's month: spring (March to May) rain, summer (June to August) nothing, autumn (September to November) leaves, winter (December to February) snow. In summer the idle timer is not armed, and the command shows "No weather in summer" in the status line instead of starting.

### 10.2 What it shows

- The app stays drawn as it is underneath, not dimmed; each particle replaces the one cell it is in, over text, borders and the status line alike, and the cell shows the app again once it moves on. Wide characters are covered or shown whole, never half.
- **Autumn:** leaves in several warm colors (red, orange, yellow, brown) fall slowly, tumbling and drifting sideways, and settle on the bottom row or on the leaves already there.
- **Winter:** snowflakes of a few sizes fall slowly with a sideways drift and settle into drifts, smoothed so a pile has no single-column spikes.
- **Spring:** rain falls fast and slightly slanted and splashes on the bottom row; it does not pile up.
- **Piles** start empty each time the weather starts and grow slowly, taking several minutes to build; no column grows past a third of the screen's height, and what lands on a full column vanishes. A resize ends the weather, so piles are never re-fitted.
- **Glyphs** follow the icon setting (§7): Unicode with icons on, plainer Unicode with them off, and plain ASCII characters when the locale is not UTF-8. No emoji, since their width differs between terminals. The implementing thread picks the glyphs.
- **Colors** vary per particle with truecolor, use the nearest 256-color shades without it, and are left out with `NO_COLOR`, where the shapes alone show the weather.

### 10.3 Implementation

- `ui::weather` owns the particles and piles and paints them onto the buffer after the widgets and after `ui::animation`'s effects; the core knows nothing of it (code-quality.md, UI-independent core). The UI tracks the time of the last input.
- While idle and not playing, the UI asks the event loop for one deadline, the moment the idle time runs out; while playing it asks for frames at up to 30 fps, advanced by the elapsed time the event loop measures. When it is off, nothing is asked.
- Randomness comes from a small seeded generator in the UI, not a new dependency, and the season from a date the UI is given, so tests are deterministic.
- Tests render through `TestBackend` with a fixed seed, clock and date: the weather starts at the idle time and not before; the ending input is not applied and the next frame equals the frame before the weather; piles never pass a third of the height; each season, summer and the settings that turn it off; and no deadline is asked when it is off.
